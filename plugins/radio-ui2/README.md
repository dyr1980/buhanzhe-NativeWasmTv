# 玻璃唱片电台界面（radio-ui2）

第二套唱片界面（`optical`）依据提供的参考视频重绘：深蓝背景、透明玻璃盘、旋转银色金属环、黑色内环和小型银色轴心，以及玻璃上、下两层下落光点。插件内部修订号为 5，仍实现 `RadioUi` API 1。

## 选择与下载

在原生“功能设置 → 偏好设置 → 唱片界面”，或“网页管理 → 高级设置 → 电台界面”选择样式。界面列表由 `plugins/radio-ui/catalog.json` 提供，用户无需输入下载地址。

电台渲染 JAR 只在首次使用时下载，不打入 APK。下载成功后以 SHA-256 命名存放于私有目录，后续可离线加载。切换保留音频播放器、播放状态和原始封面；手势或切台过渡进行中时延后替换。第二套使用参考视频中的银色轴心；保留的封面可继续用于经典唱片。

修订 5 起本 JAR 仅声明 `optical` 并省略经典唱片贴图；预烘焙银轨以一张共享纹理绘制，避免旧 Skia 的角向色带。本次仅更新 `optical` 条目。经典唱片继续使用固定提交 `74f7baa57d61ff80a47d6521ae18e336eccc91e3` 中的旧 JAR，SHA-256 为：

```text
0c2f6249d1ea81d58671c6612fdcdac4237e3bdcfc54a55e162ca958e988ad0b
```

第二套的发布路径为：

```text
https://raw.githubusercontent.com/buhanzhe/NativeWasmTv/master/plugins/radio-ui2/dist/radio-ui2.jar
```

发布时先上传最终 JAR，再把在线目录和 APK 初始目录中 `optical` 的 URL、SHA-256 同步至最终产物。每次覆盖该路径都需要更新目录哈希。已成功下载的选中界面冷启动继续使用原缓存；用户刷新选项并再次选择第二套后才应用新描述。

## 动效与性能

- `OpticalMotionView` 提供唯一累计播放时钟。银色金属环与轴心共用该时钟，每 20 秒旋转一周；前、后粒子层读取同一时间，暂停和恢复保持相位连续。
- 外玻璃边缘和内环的环境反光保持固定角度，旋转的金属反射单独变化，避免整个玻璃边缘跟随转动。
- `GlassParticles` 使用固定种子生成两层光点：远层先绘制，透过玻璃的透明部分可见，被不透明金属和内环遮挡；近层最后绘制，可经过玻璃、金属环和轴心上方。粒子沿屏幕坐标下落，大小、速度和亮度分层。
- 切台快照保存玻璃盘和轴心材质。粒子继续留在场景坐标中，避免快照移动时出现重复光点。
- 画笔、渐变、矩阵、粒子参数和光点贴图预先生成并复用。逐帧不生成 Bitmap，不依赖模糊滤镜或音频频谱检测。轴心与内圈纹理缓存绘制；过渡快照只在手势、切台时生成。
- 光效在 Android 4.4 及以下按约 25 fps 调度，较新设备按约 30 fps 调度。暂停、宿主不活跃、不可见和脱离窗口时停止动画回调。

## 构建

```powershell
python plugins/radio-ui2/src/build.py --sdk D:/android/sdk --java-home YOUR_JAVA8_HOME
```

需要 Java 8、Android Build Tools 30.0.3（D8）和 android-30 平台。默认生成修订 5；可通过 `--version` 指定内部修订号。

构建缓存位于 `.codex-tmp/radio-ui2/build`；产物固定为 `dist/radio-ui2.jar` 和 `dist/radio-ui2.sha256`。JAR 包含 `classes.dex`、`radio-ui.json`、界面资源，不重复打包宿主 `RadioUi` 接口。D8 以 `--min-api 14` 构建，保留 Android 4.4 的加载与 Canvas 绘制路径。

宿主校验下载大小、SHA-256、API 版本及最低系统版本，按哈希分离只读 JAR 和 ClassLoader。下载、校验或初始化失败会保留已有界面，音频仍由宿主管理。SHA-256 用于文件完整性校验。

## 管理接口

- `GET /api/radio-ui`：状态与可选样式。
- `POST /api/radio-ui`，JSON `{"id":"optical"}`：选择第二套；`{"id":"classic"}`：选择经典唱片。
- `POST /api/radio-ui`，JSON `{"refresh":true}`：刷新在线目录。

接口不接受 URL 配置或原始 JAR 上传。

## 验证记录（2026-10-18）

小米 6 / Android 7.1.1 独立诊断包的 18 项完整验证通过：真实 HTTPS 下载与缓存复用、保留正在播放的音频及封面、1080×2400 六个相位、粒子确定性与实际遮挡、暂停像素稳定、隐藏/后台/脱离窗口停帧、手势中延后替换，以及切台快照交接。切换与生命周期验证未增加音频请求。

测试直接比较无粒子/仅后层/仅前层的原生画面：后层在不透明盘面内部改变 0 像素，在透明玻璃环内改变 895 像素；前层在不透明盘面内部改变 3247 像素。连续 24 次离屏软件绘制未增加 Java 堆分配。真实窗口 6 秒主线程 vsync 回调间隔 P95 为 16.42ms，未出现超过 26ms 的间隔；这不是宣称动画为 60fps。动画仍按 25/30fps 调度。整进程 CPU 样本包含音频解码及宿主，约为一个 CPU 核的 46.1%。软件离屏绘制数据与 GPU 窗口表现应分别理解。

实际横屏动效录屏及逐帧参考对照位于 `.codex-tmp/glass-record/report.html`；仪器测试为 `GlassRecordInstrumentation`。JAR 为 223,943 字节，比旧插件增加 30,971 字节，主 APK 仍不包含电台渲染 JAR。

本轮 Android 4.4 设备尚未接入，真机表现待验证。此前旧版柔光界面的设备测试和性能数据不作为本次玻璃唱片实现的验证结果。
